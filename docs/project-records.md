# 프로젝트 기록 올리기

프로젝트 소개는 기존 노션 **프로젝트 (Projects)** DB에서 관리한다. 새 실험 글은 **글 (Posts)** DB에 별도 페이지로 작성하고 `Project`에 해당 프로젝트를 연결한다.

## energy-forecast에 첫 글 올리기

1. [준비된 비공개 초안](https://app.notion.com/p/40c1dbb7727c81f39f40f0b2e051ace1)을 연다.
2. 제목을 바꾸고, 페이지 본문에 작성한 글을 붙여 넣는다. `Project`는 태양광·ESS 프로젝트로 연결되어 있다.
3. `Date`에 발행일을 입력한다. 카테고리와 태그, 페이지 커버는 필요할 때 추가한다.
4. 공개할 준비가 되면 `Published`를 체크한다. 노션 직접 연결을 설정한 사이트에서 약 1~2분 뒤 새로고침하면 프로젝트 소개 하단과 왼쪽 메뉴에 글이 표시된다.

글을 더 쓸 때는 [energy-forecast · 실험 기록 보기](https://app.notion.com/p/de67a995c5cf45f2bcddda857a9a30fa?v=40c1dbb7727c813db14b000c81d804f8)에서 새 페이지를 만든다. `Project`가 태양광·ESS 프로젝트에 연결되어 있는지 확인한다.

식물 진단 프로젝트 글은 [plant-diagnosis · 개발 기록 보기](https://app.notion.com/p/de67a995c5cf45f2bcddda857a9a30fa?v=40c1dbb7727c8123b130000ca6862b9a)에서 같은 방법으로 작성한다.

## 소개와 게시글의 구분

| 작성할 내용 | 노션 위치 |
|---|---|
| 프로젝트 전체 소개 수정 | 기존 프로젝트 (Projects) DB의 해당 페이지 |
| 프로젝트에 추가할 실험·개발 기록 | 글 (Posts) DB의 새 페이지, `Project`에 해당 프로젝트 연결 |
| 일반 Study Notes | 글 (Posts) DB의 새 페이지, `Project`는 비워 둠 |

`Project`에는 글 하나당 프로젝트 하나만 연결한다. 프로젝트 기록은 Study Notes 카테고리 목록과 구분되며, 같은 프로젝트의 글끼리 이전·다음 글로 이동한다. 소개 하단의 GitHub 등 기존 Links는 그대로 유지한다.

## 사이트 반영

- 노션 글 수정은 별도의 배포 없이 반영된다. 사이트는 열릴 때와 열린 탭에서 1분 간격으로 최신 내용을 확인한다. 처리 시간까지 포함해 약 1~2분 뒤 확인한다.
- `Date` 내림차순으로 ‘최근 글부터’ 정렬한다. `Date`가 비어 있으면 노션 페이지 생성일을 사용한다.
- `Published`를 해제하거나 글을 삭제하면 다음 목록 갱신에서 사이트 목록에서 빠진다.
- 디자인과 기능을 수정했을 때는 기존처럼 코드를 커밋·푸시해 Vercel에 배포한다.

`data/posts.json`과 `data/projects.json`은 기존 내용을 보관한 스냅샷이다. 직접 편집하지 않는다. 서버가 노션의 `Project` 관계와 프로젝트의 `Slug`(현재 `p2`/`p1`)를 읽어 글을 연결한다. 일반 Study Notes는 `Project`를 비워 둔다.

## 처음 한 번 필요한 Vercel 설정

1. Vercel에서 `study-gazette` 프로젝트를 열고 **Settings → Environment Variables**로 이동한다.
2. **Production** 환경에 `NOTION_TOKEN`을 등록한다. 기존 GitHub 동기화에서 사용하던 노션 연결 키를 노션 연결 관리 화면에서 확인해 입력한다. 키는 채팅이나 코드에 붙이지 않는다.
3. 글 DB와 프로젝트 DB가 그 노션 연결에 공유되어 있는지 확인한다. 기존 동기화와 같은 연결이면 기존 권한을 사용할 수 있다.
4. 이번 코드 변경을 배포한다. 이미 배포한 뒤 키를 추가했다면 Vercel에서 Redeploy한다.
5. 사이트의 `/api/content` 응답에 `source: "notion"`이 표시되는지 확인한다. `snapshot`이면 노션 키가 아직 적용되지 않은 것이다.

DB 주소는 코드에 기존 값이 들어 있어 별도 입력이 필요 없다. 다른 DB를 쓸 때만 `NOTION_DB_ID`, `NOTION_PROJECTS_DB_ID`를 등록한다. 로컬에서 실제 노션 연결을 확인할 때는 `.env.local`에 같은 값을 등록한다.

## 처리 방식과 기존 Actions 기록

목록과 수정 날짜는 분 단위로 확인한다. 본문은 수정 날짜가 같은 캐시와 기존 스냅샷을 재사용한다. 새 글이나 수정된 글의 본문만 다시 읽으며, 노션 임시 사진 주소가 들어 있는 본문은 주소 만료를 피하려 10분 단위로 갱신한다.

GitHub Actions의 기존 동기화는 자동 일정과 실제 실행을 중단했다. 워크플로 파일과 과거 실행 기록은 삭제하지 않았다. 기존 로그는 저장소에 설정된 보관 기간이 지나면 GitHub 정책에 따라 정리된다.
